# 车机音乐 Agent 评估工具

将测试同学导出的 Excel 转成带逐条标注的 Excel，以及可用浏览器打开的整体报告。适用于 Windows 本地使用，不需要 Codex、Postman 或 IDEA。

## 第一次使用

1. 安装 Python **3.11 或更新版本**（推荐 3.12/3.13），安装时勾选 **Add python.exe to PATH**，保留默认的 Tcl/Tk 组件。
2. 将工具压缩包**完整解压**到普通文件夹，例如 `D:\音乐评估工具`。不要在压缩包内运行。
3. 双击 **安装并启动.bat**。首次会创建独立的 Python 环境并安装 openpyxl，通常需要联网访问公司允许的 Python 包源。
4. 窗口打开后选择测试 Excel 和输出目录。首次可保持勾选“仅规则检查”，点击“开始评估”。
5. 结果保存到输出目录，包含评分 Excel、HTML 报告和运行记录 JSON。点击“打开最新报告”，或双击 HTML 文件查看。
6. 后续双击 **启动工具.bat** 即可，不必每次安装。

如果双击时提示找不到 Python、依赖下载失败或公司电脑权限受限，请将终端错误提供给 IT。不要关闭 TLS/证书验证。公司使用内网包源时，请 IT 使用受信任的 pip 配置；不要随意添加 `--trusted-host`。

## 接入公司模型

将整个工具包和 [给公司模型的配置要求.md](给公司模型的配置要求.md) 交给公司内部模型或研发同学。工具使用 OpenAI 兼容的 **Chat Completions HTTP API**，无需在电脑安装 OpenClaw。

窗口中填写：

- **API地址**：由公司提供，含正确路径。例如 `https://公司网关/v1`，工具自动追加 `/chat/completions`；完整地址也支持。OpenClaw 是否启用该路由、允许的模型名和鉴权方式需由公司确认。
- **模型名称**：填写公司批准的精确名称。
- **临时密钥**：如需要，填写公司合法分配的凭据。它只用于本次运行，不保存到配置文件、Excel、HTML或运行记录；关闭程序后需重新填写。不要发给外部聊天工具。

也可点击“读取配置”选择公司同事生成的 JSON 文件。`config.example.json` 是结构示例，其地址和模型名**不可直接使用**。取消勾选“仅规则检查”才会调用模型。先拿1～2条测试验证接口，避免一开始大批量消耗额度。

调用模型会发送当前关键帧、当前会话前轮数据、参考资料和评分标准。不发送原人工“是否通过/存在问题”和“标注备注”列，避免答案泄漏。配置、脱敏和数据发送应按公司批准范围使用。

**仅规则检查不是完整评分**：它可发现明确的漏调用、播放失败等；准确性、语义、音乐质量需要模型和必要证据。没有连接、请求失败或模型结果格式错误时，相应项目待复核，不生成假的PASS或质量分。

## Excel 如何填写

支持你提供的原始12列格式，字段名须保持一致，表头位于第1行。多个含 `Query` 列的工作表都会处理，空表跳过。每条有Query的行会被评估。仅支持 `.xlsx`，不支持 `.xls`、宏工作簿或公式数据；公式请先粘贴为值。

推荐使用包内 **评估输入模板.xlsx**；也可在窗口点击“生成Excel模板”。模板有填写说明和两行**未填结果的示例**，请替换为真实测试数据。

多轮测试每轮一行，填写同一“会话ID”和从1开始的“轮次”，不能重复。前轮可以在表中更靠后，程序按轮次建立上下文。工具入参、响应及播放结果只记录当前轮；没调用就留空。不同工作表中的会话互不关联。

可选但推荐的列：

| 列名 | 作用 |
| --- | --- |
| 预期行为 | 只搜不播、又搜又播、先搜后播、其他。优先于模型判断；先搜后播指继承歌单的播放轮 |
| 预期需搜索 | 是/否；继承上轮播放填否，要求“换一批”通常填是 |
| 原始NLG文本 | 语音合成前文本，优先于asr新；没有则按语音转写处理 |
| 评测日期 | 原测试发生日期，热点判断不能拿评分当天替代 |
| 参考资料 | 已核实的歌名、歌手、语言、歌词、电影归属、事件日期等，附来源及必要摘录；仅填URL不会自动联网读取 |
| 时效窗口 | 例如“测试日前14天”，明确“最近”的范围 |
| 配对组ID / 配对类型 | 恰好两条一组；类型填“同诉求重复”或“不同诉求对比” |

列表推荐每行一首 `歌名 - 歌手`，保留Live/翻唱等版本信息，也支持JSON数组。实际标签和通道取最后一项。原样例中把第1轮、第2轮工具输出混在一个单元格的记录，会暂不评分并要求拆行。

## 如何看结果

原文件不改写，原人工标注保留。结果新增 `自动_` 列。重复评估已有结果文件时，新增列带运行ID，不覆盖前次自动标注。

- **自动_PASS_FAIL**：只填 PASS / FAIL；证据不足时留空，报告显示待定。
- **自动_复核状态**：单独说明是否还需复核。即使回复未评估，有明确播放失败证据仍可FAIL并待复核。
- **自动_问题标签 / 问题证据**：传参错误、落域错误、调用工具错误，可同时存在。标签与PASS/FAIL独立；内部代码根因需研发进一步确认。
- **搜索/播放逻辑、多样性、时效分**：分别评价候选列表和实际播放列表，范围0～5；没有列表、不适用或证据不足则空白，空白不是0。
- **评分理由 / 复核原因**：说明判断依据和需要补充什么。

PASS/FAIL采用你约定的最终结果规则：回复要准确且满足需求；有播放意图时实际播放列表必须存在。只搜不播没有播放结果不算失败，发生不必要播放则算行为不符合需求。没调用搜索不自动FAIL，可单独标工具错误。输出列表仅代表按测试导出协议播放成功，工具没有连接车机验证声音。

`asr新` 的合理同音差异不直接FAIL。ASR与回复错误无法区分时待复核。具体事实没有参考依据时，模型不能把自己的记忆当作已核实证据；你可以补充资料或原始NLG重跑。

报告包含总量、PASS/FAIL/待定、判定覆盖率、已判定样本通过率、行为分类、问题分布、质量均分及逐条理由。**待定不计入通过率分母**，所以必须同时看覆盖率。报告是本次自动运行结果；手动修改Excel不会自动更新HTML，建议在Excel单独记录人工复核，不覆盖自动列。

## Benchmark 第一版范围

详见 [评分规则.md](评分规则.md)。本版本不是把全部五个维度机械地合成一个总分：

- 逻辑自洽、多样性：逐列表评估，必须结合用户约束。
- 时效性：需要日期、时间窗口及事件资料；没有证据不打分。
- 同诉求重复 / 不同诉求对比：仅做精确歌曲文本的 Jaccard 重叠率，不把低重叠自动当高质量。不同版本、拼写差异尚不做实体归一。

第一版先用于辅助标注，不建议直接替代人工验收。建议用你已标注的样例逐条校准，再扩大批量。固定测试集、模型版本、资料与评分规则版本后，版本比较才有意义。

## 给研发的运行方式

```bash
python -m pip install -r requirements.txt
python app.py
python evaluate.py 示例.xlsx --output outputs
python evaluate.py 示例.xlsx --output outputs --config config.local.json
python evaluate.py --template 评估输入模板.xlsx
python -m unittest discover -s tests -v
```

CLI模式从配置指定的环境变量读取密钥，不支持将密钥作为命令行参数。GUI在后台线程评估，停止会等待当前HTTP请求（含短暂重试）结束，再导出已处理结果。被停止的报告记录已处理数量，未处理记录不算入结果。

已在当前Linux环境通过自动化测试、样例导出及本机模拟兼容HTTP接口测试。**尚未实测Windows桌面界面和公司真实Gateway**，需在工作电脑完成首次验证。
